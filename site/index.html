How it works

Defer the irreversible.

Most undo tries to reverse an effect that already happened. takeback holds the effect back instead. During the window nothing has run, so undo just cancels a pending intention. There is nothing to roll back. It is Undo Send, generalized to everything an agent does.

proposed

The agent declares intent, description, and a diff. High severity waits here for a human.

→confirm
pending

The countdown runs. The action is visible, cancelable, and completely inert.

→grace elapses
committed

The effect runs exactly once. Never on propose, never on optimistic apply.

✕ rejecteddeclined at the preview, nothing ran ↶ undonecanceled mid window, nothing ran

The whole trick in one sentence: onCommit fires only on the pending to committed transition, so an undo is not a rollback. It is a veto.

Two lines of integration

Headless core. Thin React layer.

The engine has zero dependencies and zero React imports. Run it in Node, vanilla JS, or any framework. The React bindings add a provider, two hooks, and four drop-in components.

app.tsx react 
import { UndoToast, useReversible } from "takeback";

const { propose } = useReversible();

propose({
  intent: "send-email",
  description: "Send follow-up to 3 clients",
  severity: "medium",  // 8s undo window
  onCommit: async () => {
    await api.sendEmails(); // runs only if
  },                        // nobody hits Undo
});
agent.ts headless 
import { ReversibleEngine } from "takeback/core";

const engine = new ReversibleEngine();

const { controls } = engine.propose({
  intent: "delete-files",
  description: "Delete 12 stale build files",
  severity: "high",  // waits for confirm
  onCommit: () => api.deleteFiles(),
});

controls.undo(); // the effect never runs

Built for production

Small surface. Sharp edges filed down.

0runtime dependencies
~9 kBof ESM, fully typed
20deterministic engine tests
5phases, one state machine

Headless first

A framework-agnostic state machine at the core. React is an optional peer dependency, not a requirement.

Severity aware

Low and medium actions run optimistically with an undo window. High severity waits behind a confirm gate.

Accessible

Focus-trapped alert dialog, Esc to cancel, polite live regions, and full prefers-reduced-motion support.

Deterministic

The clock is injected. Tests drive time with advance() and run in milliseconds with no real timers.

Failure contained

An async onCommit that throws stays contained. The queue keeps running and the error goes to your handler.

Composable UI

UndoToast, PreviewDialog, CountdownRing, and ActionDiff read engine state and stay dumb. Styling is opt-in.
